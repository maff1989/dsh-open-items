# Accessibility: static audit and manual browser checklist

Open Items is a DSH browser plugin: the inbox page, the resolved register, the
export dialog and the in-session card all render in the harness web UI. This
document records what the repository can verify **without a browser**, what a
human must confirm in one, and the contract the code is expected to keep.

## Automated audit

```bash
node scripts/a11y-audit.mjs           # report
node scripts/a11y-audit.mjs --strict  # release gate: exit 1 on any HIGH finding
node scripts/a11y-audit.mjs --json    # machine-readable
```

The scanner (`scripts/a11y-audit.mjs`) walks `src/client/**/*.{ts,tsx,css}` and
checks the mechanical contracts:

| Rule | Severity | Contract |
| --- | --- | --- |
| `button-name` | medium | a button with empty/icon-only content must carry `aria-label`/`aria-labelledby`/`title` |
| `interactive-semantics` | high | a clickable `div`/`span` must have `role`/`tabIndex`/`aria-*` (or be `stopPropagation` plumbing) |
| `form-label` | medium | `input`/`textarea`/`select` must have `aria-label(ledby)`, `id`, or be wrapped in a `<label>` |
| `image-alt` | high | `<img>` must have `alt` |
| `live-region` | high | async completion surfaces must announce via `role="status"`/`"alert"` or `aria-live` |
| `reduced-motion` | medium | the stylesheet must honour `prefers-reduced-motion` |
| `focus-visible` | medium | the stylesheet must keep a visible focus indicator |
| `status-not-colour-only` | medium | status surfaces must carry text/aria/role state, not only colour |

**Result of the rc2 release run (2026-11-14, `0.1.0-rc.2`) — PASS:**

```
a11y-audit: scanned 49 browser source file(s)
  findings: 0 high, 0 medium, 0 low
  PASS live-region: async surfaces announce through role=status/alert or aria-live
  PASS reduced-motion: stylesheet honours prefers-reduced-motion
  PASS focus-visible: stylesheet keeps a visible focus indicator
  PASS status-not-colour-only: status surfaces carry text/aria/role state, not only colour
```

Interpretation: all eight mechanical contracts hold on the rc2 release tree
(the rc1 record said "31"; the rc2 client scan covers 49 browser source files).
The **S-19 rendered visual review / manual browser pass below remains a
required post-release manual sign-off** and is not claimed passed. The scanner is
a **heuristic**, not a WCAG conformance proof: a passing scan only means the
cheap structural mistakes are absent (the first audit revision produced nine
false positives when it did not resolve `<label>`-wrapped radios and
`{t('…')}` text content; the heuristics were tightened rather than the findings
hidden). The manual list below is still required.

## Manual browser pass (required before release)

Run against the installed `web` profile, at 1280 px and 200 % zoom, in both
themes, with a screen reader (VoiceOver/NVDA) and keyboard only.

### Keyboard

- [ ] Tab reaches every interactive element in reading order: filters, search,
      group switch, session/workspace lens chips, row buttons, register tab,
      export controls, card option/text controls, dialog buttons.
- [ ] No keyboard trap; Escape closes the export dialog and the card's expanded
      controls; focus never disappears behind the dialog.
- [ ] A row is activatable with Enter/Space (rows are real `<button>`s).
- [ ] `:focus-visible` outline is visible on every control in both themes.
- [ ] After answering/dismissing, focus stays on the acted-on row or moves to a
      sensible neighbour, not to `<body>`.

### Screen reader / announcements

- [ ] Loading, offline/error, and "refreshing" states announce once (the page
      uses `role="status"`/`alert` plus a visually-hidden refreshing line).
- [ ] After an answer, the register's in-flight state and the counts change are
      announced; "earlier records pruned" is announced when the flag is set.
- [ ] Card state changes (sending, sent, failed, already recorded) are announced
      by the live region, not only by colour.
- [ ] Option groups are announced as radio groups with their label; the approval
      choices read as allow/deny options.
- [ ] The dialog is announced as a modal dialog with its title
      (`role="dialog"`, `aria-modal`, `aria-labelledby` are present).

### Visual and cognitive

- [ ] Status is never conveyed by colour alone: every state chip has a text or
      icon label; verify at reduced colour perception (grayscale screenshot).
- [ ] Contrast of text, chips and focus rings is sufficient in light and dark
      themes (automated scan cannot measure contrast).
- [ ] 200 % zoom / 320 CSS px width: no horizontal scroll, no clipped controls,
      counts remain readable.
- [ ] Motion: with "reduce motion" enabled in the OS, no animated transitions
      play (the stylesheet's `prefers-reduced-motion` block covers the shipped
      transitions; verify the card and dialog).
- [ ] Touch/pointer targets are at least 24×24 CSS px in the panel-sized layout.

## Known manual findings (rc1; rc2 re-checks them at Gate C)

These are **not** detected by the static scanner and require either a browser
check or a change owned by the client work packages:

1. **Export dialog focus management — rc1 finding, fixed by the rc2 `Modal`.**
   rc1 rendered a hand-rolled dialog that moved no focus and trapped none. rc2
   replaces it with the shipped `Modal` (focus trap, Escape, mask, restore on
   close), and the manual pass must confirm focus enters the dialog, Tab cannot
   leave it, and focus returns to the trigger.
2. **`aria-expanded` without `aria-controls`.** The card's "more options" button
   exposed its state but not the controlled region id; rc2 now uses shipped
   `Menu`/`Modal` where the role fits — re-verify screen-reader output and add
   `aria-controls` if a hand-built disclosure remains.
3. **Announcement of count changes.** Counts live in the page header; rc2 now
   ships the app-wide `Toast` and a `role="status"` result announcement — confirm
   a screen reader announces the result and the changed count after a reply.
4. **Locale coverage.** Strings exist for `en` and `zh`; verify the screen-reader
   pronunciation and that `lang`/`dir` are set by the harness shell rather than
   the plugin.
5. **Reduced motion and primitive ownership (rc2).** `AnimatedRows`, `Modal`,
   `Menu` and `Toast` come from the primitives package, which owns their motion
   and focus behavior; verify the plugin did not override it and that
   reduced-motion still disables list animation and dialog fades.

## Scope notes

- The static scan only covers `src/client/**`; host-side copy that reaches the
  screen is rendered by these components, so the scan is the right surface.
- The plugin does not ship custom focus styles for harness-owned primitives
  (buttons, menus from `dsh-client-ui-primitives`); those inherit the harness's
  own accessibility, and the manual pass should include one such primitive
  (e.g. a menu) to confirm the plugin did not break it.
- Export files (CSV/JSONL/HTML) are data artifacts, not interactive surfaces;
  the HTML export is static, script-free, CSS-only, and readable with styles
  disabled.
