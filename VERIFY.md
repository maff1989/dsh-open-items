The rc2 numbers below are **raised-draft counts, not open-item counts**: the rc.1
harness counted every artifact a fold raised and never subtracted the closure
that artifact received later in its own log. Re-running the same rc.1 folds with
the corrected accounting (each artifact's closure is subtracted; the closure
invariant is now a **declared per-family closing-detector map** instead of a
`/close|settle|resolve/` string match) gives:

```
structural items: 1 open at log end (target ≤20 — MET; raised=10, closed=9, closures=40)
invariants: root-only violations=0, todo-derived=0 (needs-you=0),
            no unconditional detector closer=1, unclassified families=0
```

- **True cold-open count: 1** — the blocked approval
  `approval:call_00_04yfbkg4E0xcF44XWPZO1187` (rejected, no granted retry).
  The other 9 raised drafts were closed by later events in their own logs.
- The original `per-kind: question=8, approval=1, follow-up=1` line therefore
  counted **raised** questions and a **raised** unsettled job, not unanswered

## 8. Post-rc2 fix — authored approvals and the session label (2026-11-14)

The rc2 manual sign-off item was itself the reproduction. It was an authored
`approval` item (raised by the `open_items` tool in
`session-e5a224dc-f896-4ab4-b27d-5aa39b7b5b9d`, `source.callId`
`call_01_eOZ0LGmZVq5ViOIC1Vx94116`, no `approvalId`, `detectedBy: ["tool"]`,
`dedupeKey: authored|…`). Because no shipped `approval/request` existed behind
it, the browser held no live card, so Allow/Deny stayed disabled with "Open the
session to decide this approval" — and the session had no approval card to open.
The same item rendered as `(deleted session)` because an authored raise stamps no
`source.sessionTitle`, and the UI treated a missing title as a deleted Session.

Verified root cause (not a teammate-rollup defect): the raise tool call is in the
root Session's log at turn 7 / step 107; the stored record has no `raisedBy`, and
the shipped routing contract only had a live-card approval path. Authored
approvals (root or subagent-raised, the latter stamped with `raisedBy`) had no
answer path at all, and the DESIGN §6.4 "Approve & retry" track-3 fallback was
documented but not implemented.

### Fix (files in `dsh-open-items/`)

- `src/shared/item-origin.ts` (new): `isAuthoredItem` / `isAuthoredApproval` —
  the one authored-vs-mirrored predicate both halves use; existing records
  classify correctly from their dedupe key and detection sources.
- `src/host/delivery.ts`: an approval payload is legal on `client-settle`
  (mirrored) and `session-message` (authored); the origin/track mismatches are
  refused before any session work; the authored decision sends the deterministic
  notice `Approved (one-off).` / `Denied.` (+ the user's note) and persists a
  queued `session-message` delivery carrying the approval payload; a decision
  that would only be recorded is refused instead.
- `src/host/tools.ts`: authored raises stamp the root Session title on
  `source.sessionTitle` (best-effort, cosmetic).
- `src/client/data/settle.ts`: authored approvals enable without a carrier and
  always route `message`; mirrored approvals keep the live-card path unchanged.
- `src/client/ui/{row,detail}.tsx`, `answer/ApprovalConfirm.tsx`: authored
  consent copy ("sends your approval to the session…"), no false
  "open the session" hint, same Allow once/Deny labels.
- `src/client/ui/panel/{panel-store,PanelRow}.tsx`: the panel names
  `session-message` for approval decisions and treats the shipped confirmation
  as the explicit wake consent.
- `src/client/ui/card/*`: approvals point at Open Items; plan reviews keep their
  own pointer.
- Session labels: `detail.unknownSession` → `detail.untitledSession`; a
  catalogue-backed `SessionTitleResolver` is threaded through the page, group
  headings, row/detail/confirmation and register surfaces, so the live title is
  preferred and `(deleted session)` can no longer be claimed.

### 9.3 What the evidence covers beyond the aggregate numbers

- **Settings → Open Items** (`settings.section`, id `open-items`, order 40):
  defaults `modelNudge: false` / `proseCandidates: true`; CAS read/write over the
  existing `settings` endpoint; conflict value (not an error); no Save button; no
  settings request until the page mounts; refresh on `connection/reset`; the
  versioned record shares the existing `meta` table (storage-domain version stays
  1). Unit + client tests cover the page, toggles, CAS conflict and error paths.
- **Model nudge:** the `open-items:nudge` `systemPrompt` section (order 60) is
  registered only while `modelNudge` is on and disposed immediately when off; a
  profile without the service degrades silently; the setting gates it (unit
  coverage).
- **Prose gate / todo aggregate (pre-prose-audit build):** strict gate rules
  (≥40 chars, marker in the last 300 chars or trailing `?`, word-bounded
  phrases, code fences ignored), deterministic fingerprint,
  question-vs-decision kind, supersede/cap closures, cold-baseline emission,
  `proseCandidates` off => no drafts; todo raise/close (capture tests). **This
  gate was rewritten on 2026-11-14** (additive per-item extraction, semantic
  kinds, per-item ids, batch-aware bounds, migration; §10) — the rules in this
  bullet describe the fallback mode only.
- **Candidate lifecycle:** `promote` (candidate only → structural, severity 2,
  blocking, history `promoted`) and `suppress` (candidate only → dismissed +
  exact-key suppressor) with CAS and suppressor-no-resurrection coverage;
  candidates are excluded from the needs-you counts (store/route/e2e).
- **Team-task disable + retirement:** the family produces no live or cold items;
  `retireTeamTaskItems()` resolves open `team/task:in-progress-orphan` rows as
  `detected-closed` code `team/task:alerts-disabled` once at activation (unit +
  service coverage; audit-visible).
- **Capture hardening:** hydration of a session's ledger on its first live event
  (one read per session per process, failures contained), the bounded periodic
  re-scan interval, archived-session exclusion, and the fold + projection
  version bump 1 → 2 together (capture/backfill tests).
- **Integration fix recorded:** `tests/e2e/composition.spec.ts` was updated for
  D3 (the abandoned `todo/write` now yields one `follow-up` candidate; candidates
  are excluded from workspace `itemCount` because
  `needs-you === Σ workspaces.itemCount`), the settings endpoint assertion now
  expects `bad-request` for the old stub shape, and promote/suppress were added
  to the endpoint-enumeration test.
